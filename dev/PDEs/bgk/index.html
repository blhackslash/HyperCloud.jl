BGK Equation

BGKEquation is a discrete-velocity model of the Bhatnagar–Gross–Krook equation

\[\partial_t f + \vec v\cdot\nabla_x f = \frac{1}{\tau}\big(\mathcal M[f] - f\big),\]

for the distribution $f(\vec x, \vec v, t)$ of a gas in $D$ space dimensions. Its moments $U = (\rho, \rho\vec u, E)$ are the conservative variables of the Euler equations, which the BGK solution approaches for $\tau \to 0$; for $\tau \to \infty$ every velocity moves freely.

Velocity space as the state vector

The velocity space is discretised by a tensor grid of Nv nodes per direction (velocity_grid), and the particle state is the vector of distribution values at the nodes: the number of equations is the number of discrete velocities. Everything HyperCloudCore offers (MUSCL, limiters, MOOD, IMEX, moving grids, the device backends) therefore runs on the BGK model unchanged. Moments are quadrature sums, $U = \sum_k w_k\,(1, \vec v_k, \tfrac12|\vec v_k|^2)\,f_k$.

Since the state is an SVector, its length drives compile time and per-particle cost. The model keeps it small in three ways:

  • Only D velocity directions. Degrees of freedom beyond the resolved velocity directions (the remaining directions of a 3-D gas and internal ones, $K = 2/(\gamma - 1) - D$ in total) are carried by a second distribution $h = \int \tfrac12|\xi|^2 f\,d\xi$ on the same nodes (a Chu reduction). The state is $f$ for $\gamma = (D + 2)/D$ ($M = N_v^D$), otherwise $(f, h)$ ($M = 2 N_v^D$). A 1-D shock tube with $\gamma = 1.4$ needs a 1-D velocity grid, not $N_v^3$ velocities.
  • Gauss–Hermite nodes (:velocity_grid => :gauss_hermite) integrate polynomials times the Gaussian of their scale exactly, so near-equilibrium flows need far fewer nodes than the uniform midpoint grid (:uniform, the robust choice for strongly non-equilibrium flows).
  • No per-velocity arrays in kernels. The equation is a small bits type (1-D nodes and weights, grid centre, $K$, $\gamma$, relaxation model); the node of a component is resolved from its index at compile time, so the flux and the dissipation unroll into straight-line code.

Collision term

The equilibrium is the conservative discrete Maxwellian of equilibrium ($f_k = \exp(\alpha\cdot\psi_k)$ with $\psi = (1, \vec v, \tfrac12|\vec v|^2)$, Mieussens' discrete entropic equilibrium, $h_k = \tfrac K2\,\hat\theta f_k$): $\alpha$ is found by a damped Newton iteration on the convex dual problem, started from the continuous Maxwellian, so the discrete moments of the equilibrium equal $U$ to round-off and the collision term conserves mass, momentum and energy exactly. A few microseconds per particle; the iteration runs inside the kernels.

The relaxation time comes from a RelaxationTimeModel: constant (ConstantRelaxationTime, Inf for free transport) or $\tau = \mu(\theta)/p$ with a power-law viscosity (ViscosityRelaxationTime).

With an IMEX tableau the collision is the implicit source BGKRelaxation. Because it conserves the moments, the implicit stage equation has the closed-form solution $f = (f^* + \lambda\,\mathcal M[f^*])/(1 + \lambda)$, $\lambda = \Delta t\,a_{ii}/\tau$, for any stiffness, which makes the scheme asymptotic preserving: at $\tau = 10^{-5}$ the BGK Sod solution is as close to the exact Euler solution as the Euler scheme itself. With an explicit tableau the collision becomes ExplicitBGKRelaxation (stable for $\Delta t \lesssim \tau$ only).

Transport

The flux is $v_{k,d} f_k$. The transport is linear and diagonal, so the Rusanov flux of every velocity is its exact upwind flux: RusanovFlux, UpwindFlux and AlignedRusanovFlux use the dissipation $|v_{k,d}|$ per component instead of the largest node speed for all components (which smears the slow velocities; on a smooth collisionless wave it costs a factor 2 to 10 in the error). max_eigenvalue is the largest node speed, which sets the CFL time step.

The PAD of MOOD (is_admissible) asks for positive density and temperature; individual $f_k$ may dip below zero.

Configuration

:PDE_name => :bgk, :PDE_D => 1, :PDE_gamma => 1.4,
:PDE_Nv => 24, :PDE_vmax => 6.0, :PDE_velocity_grid => :uniform,
:PDE_tau => 1e-3,                       # or :PDE_viscosity => μ_ref, :PDE_omega => ω
:sim_func_name => :run_bgk_simulation,  # direct and kinetic runners forward BGK runs here

Initial conditions give the macroscopic state $(\rho, \rho\vec u, E)$, exactly as for an Euler run with the same $\gamma$; every particle starts in the discrete Maxwellian of that state. The stored snapshots are the moments, so BGK and Euler runs can be compared directly (:save_relax => true keeps the distributions). Choose vmax so that the Maxwellians of the flow decay inside the grid ($|u| + 5\sqrt\theta$ or more) and enough nodes to resolve them ($\Delta v \lesssim \sqrt\theta$).

References: the collisionless model has the exact solution of analytic_closure (each velocity transported, initial data in equilibrium); for small $\tau$ use euler_limit_solution as the reference of a SimulationConfig (see the example bgk_1d_sod).

The cost per particle grows linearly with $M$ up to a few hundred equations. In 2-D the per-slot buffers of the scheme (the flux differences of every neighbour, $(D + 1) M$ values per slot) dominate the memory, about 6× the per-particle buffers, and the compile time of the first step grows faster than $M$; $16 \times 16$ velocities still work (95 s to compile, 30 µs per particle and step). About a third of a step is the collision (two equilibria per stage), a third the gradient pre-pass with the limiter, and the rest the flux pass.

API

HyperCloud.BGKEquation — Type
BGKEquation{D, M, T, NV1, NV, R} <: HyperbolicPDE{D, M, T}
BGKEquation(::Val{D}, nodes, weights, gamma, relaxation; center = 0)

Discrete-velocity model of the BGK equation ∂_t f + v·∇f = (M[f] - f) / τ in D space dimensions. The velocity space is the tensor product of the 1-D nodes (with quadrature weights, see velocity_grid) in every direction, shifted by center: NV = NV1^D discrete velocities.

The state of a particle is the vector of distribution values at the nodes, so the number of equations is the number of velocities. Degrees of freedom beyond the D resolved velocity directions (the remaining velocity directions of a 3-D gas and internal ones, K = 2 / (γ - 1) - D in total) are carried by a second distribution h (a Chu reduction, h = ∫ |ξ|²/2 f dξ over the unresolved directions): for K = 0 (γ = (D + 2) / D) the state is f (M = NV), otherwise (f, h) (M = 2 NV). Any γ thus needs only a D-dimensional velocity grid.

The macroscopic state is U = (ρ, ρu..., E) = Σ_k w_k (1, v_k, |v_k|²/2) f_k + (0, 0, h_k) (see moments), the conservative variables of the Euler equations with the same γ (euler_limit), which the BGK solution approaches for τ → 0. The collision term relaxes towards the conservative discrete Maxwellian of equilibrium (source terms BGKRelaxation, ExplicitBGKRelaxation) with the relaxation time of relaxation (a RelaxationTimeModel).

The transport is linear and diagonal (velocity k moves with v_k): the flux is v_{k,d} f_k, the Rusanov and Upwind fluxes reduce to exact upwinding per velocity (dissipation |v_{k,d}| instead of the largest speed for every component), and max_eigenvalue is the largest node speed. The equation object is a small bits type (nodes, weights, center, K, γ, the relaxation model); node indices are resolved at compile time, so there are no per-velocity arrays in the kernels.

HyperCloud.velocity_grid — Function
velocity_grid(kind::Symbol, Nv::Int, vmax::Real, ::Type{T} = Float64) -> (nodes, weights)

One-dimensional velocity nodes and quadrature weights (SVector{Nv, T} each) of a discrete-velocity model; the BGK equation uses their tensor product in every spatial direction.

  • :uniform: midpoint rule on [-vmax, vmax], v_j = -vmax + (j - 1/2) Δv, weights Δv = 2 vmax / Nv. Spectrally accurate for Maxwellians that decay inside the interval; the robust choice for strongly non-equilibrium flows.
  • :gauss_hermite: Gauss–Hermite nodes scaled so that the outermost node is ±vmax, with the weights w_j e^{x_j^2} that integrate f itself. Exact for polynomials times the Gaussian of that scale, so near-equilibrium flows need far fewer nodes (the conservative equilibrium keeps the moments exact either way). Weights come from the Christoffel function of the Hermite functions (stable for large Nv).

HyperCloud.equilibrium — Function
equilibrium(eq::BGKEquation, U::State{D + 2}) -> (f_eq::State{M}, ok::Bool)

Conservative discrete Maxwellian of the macroscopic state U = (ρ, ρu..., E): the discrete entropic equilibrium f_k = exp(α·ψ_k) (Mieussens), whose discrete moments reproduce U to round-off on the velocity grid, so the collision term conserves mass, momentum and energy exactly. α is found by a damped Newton iteration on the convex dual problem, started from the continuous Maxwellian (on a grid that resolves the Maxwellian that start is already accurate to the quadrature error, so one or two iterations suffice). With internal degrees of freedom h_k = (K/2) θ̂ f_k.

ok is false for a non-physical U (non-finite, ρ ≤ 0 or θ ≤ 0); f_eq is meaningless then. If the grid cannot represent U (e.g. a mean velocity near vmax), the iteration stops at the closest equilibrium it reaches. Allocation free, runs inside kernels.

HyperCloud.ConstantRelaxationTime — Type
ConstantRelaxationTime(tau)

Constant relaxation time τ (the Knudsen number of the non-dimensional BGK equation). τ = Inf is the collisionless (free transport) limit: the runners drop the collision term and analytic_closure returns the exact solution of the discrete-velocity model.

source
HyperCloud.ViscosityRelaxationTime — Type
ViscosityRelaxationTime(mu_ref, omega)

τ = μ(θ) / p with the power-law viscosity μ = mu_ref θ^ω (the Chapman–Enskog viscosity of the BGK model is τ p), i.e. τ = mu_ref θ^(ω - 1) / ρ. ω = 1/2 are hard spheres, ω = 1 Maxwell molecules.

HyperCloud.BGKRelaxation — Type
BGKRelaxation(eq::BGKEquation) <: AbstractImplicitSourceTerm
ExplicitBGKRelaxation(eq::BGKEquation) <: AbstractExplicitSourceTerm

The BGK collision term S(f) = (M[f] - f) / τ with the conservative discrete Maxwellian M[f] of equilibrium and τ from the equation's RelaxationTimeModel, treated implicitly (IMEX tableaus) or explicitly (explicit RK tableaus, only stable for Δt ≲ τ).

The implicit stage equation f = f* + Δt a_ii S(f) is solved in closed form: the collision conserves the moments, so M[f] = M[f*] and τ(f) = τ(f*), and f = (f* + λ M[f*]) / (1 + λ) with λ = Δt a_ii / τ. This is exact for any stiffness (τ → 0 projects onto the equilibrium), which makes the IMEX scheme asymptotic preserving towards the Euler equations. A non-physical particle state (ρ ≤ 0 or θ ≤ 0) is left untouched (zero source).

HyperCloud.run_bgk_simulation — Function
run_bgk_simulation(params::ParamDict) -> Union{AbstractSimData, Nothing}

Runs the discrete-velocity BGK model (:PDE_name => :bgk, see BGKEquation). The particle state is the distribution at the velocity nodes; the IC namespace gives the macroscopic state (ρ, ρu..., E) (initial conditions are built with M = D + 2, like an Euler run with the same γ), and every particle starts in its discrete Maxwellian. The collision term is implicit for an IMEX tableau (BGKRelaxation), explicit for an explicit one (ExplicitBGKRelaxation) and dropped in the collisionless limit (:PDE_tau => Inf). Schemes, fluxes, limiters, MOOD and the grid are configured exactly as for the other equations.

The returned snapshots hold the macroscopic moments (ρ, ρu..., E), directly comparable with Euler runs; with :save_relax => true they keep the full distributions instead. run_direct_simulation and run_kinetic_simulation forward BGK configurations here, so the method dictionaries work unchanged.

source
HyperCloud.euler_limit_solution — Function
euler_limit_solution(params::ParamDict)

Reference for BGK runs (:PDE_name => :bgk) in the hydrodynamic limit τ → 0: the exact solution of the Euler equations with the same :PDE_D, :PDE_gamma (default (D + 2) / D, as for the BGK model), initial condition and domain, i.e. analytical_solution with :PDE_name => :euler. Pass it as the reference of a SimulationConfig; it accepts any parameter set with an Euler-compatible PDE namespace.

HyperCloud.bgk_1d_sod — Function
bgk_1d_sod()

The Sod shock tube for the discrete-velocity BGK model (γ = 1.4, i.e. a Chu-reduced distribution pair on a 1-D velocity grid of 24 nodes, 48 equations) at the relaxation times τ = 1e-5, 1e-3, 1e-2, against the exact Euler solution (euler_limit_solution), which the BGK solution approaches as τ → 0. Methods: IMEX ARS222 with MUSCL2 (Venkatakrishnan limiter, or U2 MOOD) and explicit RK2 with MUSCL2 (the collision term explicit, only stable for the larger τ).
