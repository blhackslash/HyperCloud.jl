Builder API

The runners never construct solver components directly. They split the parameter dictionary into namespaces and call one build_* function per component. Every builder dispatches on a Val of a configuration value, so new components are added by defining a method, without changing HyperCloud.

Build order and context

The builders share a context::Dict{Symbol, Any}. Each one reads what earlier builders stored and adds its own result:

StepBuilderReads from contextStores
0runner—:T
1build_equation:T:Equation, :D, :M
1bbuild_kinetic_system (kinetic only):T, :D, :M, :Equationoverwrites :Equation, :M; :ImplicitSources
2build_domain:T, :D:Domain
3build_particle_grid:T, :D, :M, :Domain, :WeightConf:max_dx, :Grid
3bbuild_weights (called by step 3):T, :max_dx:interp_range
4build_flux, build_limiter, build_mood:T, :Grid (MOOD):Flux, :Limiter, :MOOD
5build_scheme:T, :D, :M, :Flux, :Limiter:Scheme
6build_tableau, build_timesteppereverything above, :ExplicitSources, :ImplicitSources:Tableau
7build_ic:T, :D, :M (macroscopic)—

The kinetic runner builds the initial condition right after step 1, while :M still holds the macroscopic size.

:T is the floating-point type (params[:T], default Float64). The runners set :ExplicitSources and :ImplicitSources to () unless a source term is added.

Unknown names raise an error naming the missing method. A complete example for initial conditions is in Initial Conditions; a new equation is described in PDE Architecture.

A custom spatial scheme follows the same pattern. The returned object must implement the interface the time steppers expect from the built-in schemes:

function HyperCloud.build_scheme(::Val{:my_scheme}, conf::Dict, context::Dict)
    T = context[:T]::DataType
    D = context[:D]::Int
    M = context[:M]::Int
    return MyScheme(T, D, M, conf[:my_param]; flux = context[:Flux])
end

:Scheme_name => :my_scheme, :Scheme_my_param => 3 then selects it.

Custom boundary conditions

:Grid_bc maps boundary tags to boundary conditions. Besides instances and the names :outflow and :fixed_dirichlet, it accepts the name of any zero-argument constructor defined in Main or in HyperCloud:

struct MyWall <: AbstractBoundaryCondition end   # plus the methods HyperCloudCore requires
params[:Grid_bc] = Dict(1 => :MyWall, 2 => :outflow)

HyperCloud.build_domain — Function
build_domain(domain_conf::Dict, context::Dict)

Instantiates the continuous GeometricDomain and parses its boundary conditions.

domain_conf[:domain] is either a shape name (:rectangular, :spherical, or a custom shape, see below) or an already-constructed GeometricDomain, which is returned unchanged. Boundary conditions are read from :bc via parse_bc, periodicity from :periodic.

source
build_domain(name::Val, domain_conf::Dict, context::Dict)

Generic fallback for custom domain instantiation. Users can extend this by defining build_domain(::Val{:my_domain}, ...). Instantiates the continuous GeometricDomain (e.g., :rectangular or :spherical) and parses boundary conditions.

source
HyperCloud.build_particle_grid — Function
build_particle_grid(grid_conf::Dict, context::Dict)

Constructs the ParticleGrid based on the configuration and resolved geometry. Extracts the number of points (Ns) and randomness_factor to compute the cell spacings (dxs), maximum spacing (max_dx), and noise parameters. Instantiates the spatial weights via build_weights, initializes a MersenneTwister RNG, and saves max_dx into the execution context for downstream use.

source
HyperCloud.build_ic — Function
build_ic(ic_conf::Dict, context::Dict)

Reads the :IC namespace and dispatches to the matching builder via Val(ic_conf[:name]). Extend it by defining build_ic(::Val{:my_ic}, conf::Dict, ctx::Dict).

source
HyperCloud.build_kinetic_system — Function
build_kinetic_system(kin_conf::Dict, context::Dict)

Constructs the kinetic equation and relaxation source term for kinetic simulations. Requires a :velocities key in the kinetic configuration dictionary. Extracts the relaxation parameter (epsilon), edge indices (indices), and interior_factor to build a Kin2Macro mapping, a LinearAdvection kinetic equation, and a RelaxationSourceTerm. Returns the tuple (eq_kin, source_term).

HyperCloud.build_scheme — Function

Constructs the primary spatial numerical scheme. Dispatches based on the :name key (e.g., :MUSCL, :Upwind, :Central, :WENO). Retrieves pre-built dependencies like the selected flux and limiter from the execution context and extracts the scheme's formal :order and :MLS_order (divergence order).

HyperCloud.build_limiter — Function
build_limiter(limiter_conf::Dict, context::Dict)

Builds the spatial slope limiter based on the :name key. Supports :none, :minmod, :superbee, :VK (Venkatakrishnan), and :BJ (Barth-Jespersen) limiters. All active limiters strictly require a :mode parameter (e.g., :hard).

source
build_limiter(name::Val, conf::Dict, context::Dict)

Generic fallback for custom spatial slope limiters. Users can extend this by defining build_limiter(::Val{:my_limiter}, ...). Supports built-in options like :none, :minmod, :superbee, :VK, and :BJ, which strictly require a :mode parameter (e.g., :hard).

HyperCloud.build_mood — Function
build_mood(mood_conf::Dict, context::Dict)

Assembles the Multi-Dimensional Optimal Order Detection (MOOD) framework. Extracts the :criterion (e.g., :U1, :U2) and :strategy (e.g., :EPD1, :SEPD0) from the configuration dictionary and builds them independently via build_mood_criterion and build_mood_strategy before combining them. U1 and U2 criteria strictly require a :delta_relax coefficient.

HyperCloud.build_tableau — Function

Parses the user-specified :stepper string and builds the corresponding Butcher tableau. Supports explicit Runge-Kutta tableaus (e.g., :Euler, :RK2, :RK3, :RK4) and implicit-explicit (IMEX) tableaus (e.g., :ARS222, :ARS233, :PRSSP3, :SSP332, :IMEXEuler).

HyperCloud.build_timestepper — Function
build_timestepper(context::Dict)

Deduces and builds the overarching time integrator based on the constructed tableau. Automatically returns a GeneralRKTimeStepper if an RKButcherTableau is present in the context, or a GeneralIMEXTimeStepper if an IMEXButcherTableau is detected.

HyperCloud.build_weights — Function
build_weights(weight_conf::Dict, context::Dict)

Constructs the meshfree Moving Least Squares (MLS) weight function. Requires a :name (e.g., :exponential or :inverse), an interpolation :range scalar, and an :alpha parameter. Computes the absolute interpolation range dynamically by multiplying the requested :range with the max_dx extracted from the execution context.

source
